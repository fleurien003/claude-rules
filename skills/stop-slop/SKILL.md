# Stop Slop (한국어판)

AI 글의 뻔한 패턴을 걷어내고 사람이 쓴 글로 만든다.

영어 글이면 `references/english/`의 원본 규칙을 따른다. 아래는 한국어 글 기준이다.

## 핵심 규칙

1. **상투어를 지운다.** "오늘은 ~에 대해 알아보겠습니다", "결론적으로", "다양한", "효과적으로" 같은 말은 내용 없이 자리만 차지한다. 목록은 [references/phrases.md](references/phrases.md).
2. **번역투를 한국어로 바꾼다.** "~에 있어서", "~를 통해", "~를 가지다", "~되어지다"는 영어 문장을 옮긴 티가 난다. 목록은 [references/phrases.md](references/phrases.md).
3. **공식 같은 구조를 깬다.** "단순히 A가 아니라 B다", 질문 던지고 바로 답하기, 무조건 셋씩 나열하기, 문단마다 한 줄 명언으로 끝내기. 목록은 [references/structures.md](references/structures.md).
4. **구체적으로 쓴다.** "분위기가 좋았다" 대신 무엇이 어땠는지 쓴다. 가격, 시간, 이름, 숫자, 직접 겪은 장면이 모호한 형용사를 이긴다.
5. **글쓴이가 보이게 쓴다.** 누가 했는지 드러낸다. "결정이 내려졌다"보다 "팀장이 정했다". 한국어는 주어를 자주 생략하니, 억지로 "저는"을 붙이지 말고 행동이 보이게만 쓴다.
6. **리듬을 섞는다.** 문장 길이를 섞고, 같은 어미("~습니다.")가 세 번 넘게 연달아 나오지 않게 한다. 줄표(—)는 고친 글에도, 바꾼 이유 설명에도 쓰지 않는다.
7. **독자를 믿는다.** 과한 친절("~해보시는 건 어떨까요?", "도움이 되셨길 바랍니다"), 변명, 불필요한 요약을 뺀다.
8. **꾸밈을 줄인다.** 강조 부사("정말", "진짜", "매우", "굉장히", "너무"), 느낌표, 이모지, 굵은 글씨는 꼭 필요한 곳에만 쓴다.

## 지키는 것

- **글쓴이의 말투를 유지한다.** 원래 반말이면 반말, 블로그 구어체면 구어체. 딱딱한 보고서체로 바꾸지 않는다.
- **사실은 건드리지 않는다.** 숫자, 이름, 날짜, 가격은 그대로 둔다. 모르는 사실이나 원문에 없는 평가("친절했다", "인기였다")를 지어 넣지 않는다. 구체적인 정보가 필요한데 원문에 없으면 `[구체적 예시 필요]`처럼 표시하고 글쓴이에게 묻는다.
- **장르 관습은 존중한다.** 블로그 리뷰의 가게 정보(주소, 영업시간), 보고서의 소제목처럼 독자가 기대하는 형식은 남긴다.

## 빠른 점검

고친 글을 넘기기 전에:

- 첫 문장이 인사나 예고("오늘은 ~ 소개해드릴게요")인가? 본론으로 바로 들어간다.
- "~에 대해", "~를 통해", "~에 있어서"가 있나? 조사 하나로 바꿀 수 있는지 본다.
- "~할 수 있습니다", "~라고 할 수 있습니다"가 반복되나? 단정할 수 있으면 단정한다.
- "~하는 것이 중요합니다/필요합니다"가 있나? 무엇을 하라는 건지 동사로 쓴다.
- "단순히 ~가 아니라 ~"가 있나? 뒤의 말만 남긴다.
- 셋씩 나열한 곳이 여러 번인가? 하나는 둘로 줄인다.
- 문단 끝이 전부 한 줄 명언인가? 몇 개는 그냥 끝낸다.
- 같은 어미가 세 번 넘게 연달아 나오나? 하나를 바꾼다.
- 강조 부사, 느낌표, 이모지가 한 문단에 둘 이상인가? 하나만 남긴다.
- 마지막 문단이 "도움이 되셨길 바랍니다", "여러분도 ~해보세요"인가? 지우거나 구체적인 한마디로 바꾼다.

## 점수

각 항목을 1~10점으로 매긴다.

| 항목 | 질문 |
|---|---|
| 직접성 | 말하는가, 말하겠다고 예고하는가? |
| 리듬 | 문장 길이와 어미가 다양한가? |
| 신뢰 | 독자를 똑똑한 사람으로 대하는가? |
| 진짜 같음 | 사람이 쓴 것처럼 들리는가? |
| 밀도 | 지워도 되는 말이 남아 있나? |

35/50 미만이면 다시 고친다.

## 결과 전달 형식

1. 고친 글 전체
2. 무엇을 왜 바꿨는지 3~5줄 (패턴 이름으로)
3. 고치기 전·후 점수
